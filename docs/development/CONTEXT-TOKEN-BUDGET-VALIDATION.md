# 问答上下文 Token 预算与批量摘要（2026-09-29）

## 本轮范围

文字问题、语音 ASR 最终转写和图片观察后的文字问题继续共用 AnswerService。未新增公共 API、数据库字段或迁移；保留完整聊天、旧摘要游标、重试、ready/revision/active_workspace、原文定位与事实核验。工作区已有的归档迁移 `0009` 属另一项未提交工作，本轮没有迁移实际业务库。

| 模型请求 | 输入试验上限 | 输出参数上限 | 完整内容取舍 |
|---|---:|---:|---|
| 知识库回答 qwen-flash | 10,000 | 2,048 | 本轮可核对原文片段最多 4,000；历史最多 2,000；当前问题、图片观察、指令、协议和余量动态占其余部分 |
| 普通回答 qwen-flash | 4,000 | 1,024 | 移除完整旧轮次；旧摘要与旧知识库回答正文不进入普通生成 |
| 意图路由 qwen-flash | 3,000 | 384 | 当前问题和已确认候选保留，先移除较低优先级的完整资料名，再移除完整旧轮次；仍包含当前库动态信息 |
| 摘要 qwen-max | 4,000 | 300 | 输入完整早期用户轮次及原摘要；失败不推进游标；候选摘要限 600 估算 Token |
| 事实支持核验 qwen-flash | 10,000 | 128 | 当前答案和所选本轮证据整体检查；超限拒绝发送 |

预检估算为 `ceil(UTF-8 字节数 × 1.1)`，另加每条消息 48、每次请求 128；JSON 使用实际 `ensure_ascii=False` 序列化文本计算。这是故意偏保守的预检，不是 qwen-flash/qwen-max 的已验证 tokenizer，也不等于供应商账单。实际 `usage.prompt_tokens`、`usage.completion_tokens` 是后续调整阈值的依据；[百炼说明](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api/)也提示字符或词数估算可能不同于模型 Token。视觉模型的图片像素 Token、LightRAG 检索/重排/入库模型的额外调用均不包含在上述**回答模型**分配内。

原文预算只限制本次发送的已核验完整块，不限制知识库总量；不截断编号、单位或限定条件。若第一块就过长，返回需缩小范围；若后续块不合预算，保留此前完整块及其匹配引用。当前问题和图片观察也不静默截断；超出输入预算时以 `answer_budget_exceeded` 保存失败，并提示缩小问题。新图片观察提示尽量不超过每图 250 字，历史已保存的较长观察继续原样读取，不能容纳时明确失败。图片模型自己的音频/像素 Token 仍以其 usage 为准。

## 摘要触发和兼容

原策略取最近 10 个已回答轮次，窗口之外新增一轮就可能再摘要一次；历史、摘要和各模型输入以字符数控制。新策略扫描至多 64 个同 revision/workspace 的已回答轮次，仅在估算历史超过 2,000 时摘要完整旧轮次，摘要后目标约 1,000；其后新增轮次在 1,000～2,000 区间内不用立即调用摘要模型。摘要仅处理用户问题主题/条件，不输入旧助手正文；普通回答不读取旧摘要，以防旧版本摘要把知识库结论带入普通回答。数据库仍保存所有完整消息。

例如 16 轮短对话若累计估算超过 2,000，会一次概括较早几轮，保留新轮原文；紧接第 17 轮仍低于 2,000 时直接复用摘要而不再请求 qwen-max。长单轮放不下时整轮排除，不把 `ORD-001`、`42 ℃` 或限定条件切成新的含义。摘要失败时保留旧摘要/游标，只按预算发送完整近期轮次；重试仍可再次尝试。并发完成的旧摘要须与提交前游标一致，且库仍 ready、revision 和 active_workspace 未变才落库。旧摘要字段不变，过大的旧文本在发送时整段舍弃，不删持久记录。

本机验证在独立初始化的 PostgreSQL 实例（回环端口 55441）及每项随机 schema 中执行：相关问答、语音、图片集成 77 项通过；修正历史测试的固定“第 11 轮摘要”假设后，全套 557 通过、4 跳过；最后抽取共享摘要提示词后，受影响的 50 项集成与预算回归再次通过。Ruff 与 Python 编译检查通过。测试 PostgreSQL 已停止；自动审批策略拒绝递归清理本轮自建的 `.local/context-budget-f00520c522d248a29d9704ad92f32746` 目录，暂留忽略目录，不是运行中的服务或实际业务数据。

前端受影响的 `src/app.test.ts` 43 项通过，typecheck、lint、build 通过。前端全套 `pnpm test` 为 225 通过、4 失败；失败集中在本轮开始前已有的未提交 React UI 细化变更（标签、资料入口和选库断言），与本次后端预算路径无直接交集。本轮保留该工作，不把前端全套标为通过，也不改写另一项 UI 工作的预期行为。GitHub CI 未运行本轮未提交代码。
