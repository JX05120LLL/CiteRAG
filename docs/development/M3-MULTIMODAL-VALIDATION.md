# M3 图片提问增量与验收边界（2026-09-28）

## 当前实现

本轮将图片理解模型选为百炼 `qwen3.8-omni-flash`，仅用于**非实时图片观察**。文字与语音最终转写仍共用原 AnswerService；实时语音仍由火山 ASR、本地 VAD、现有回答模型与 MiniMax TTS 组成。Omni Flash 官方支持文字、图片、音频、视频输入，但该型号输出只有文字；不能据此宣称已实现视频/音频文件上传或实时语音替换。模型能力以[官方型号说明](https://help.aliyun.com/zh/model-studio/qwen3-8-omni-flash)和[非实时调用说明](https://help.aliyun.com/zh/model-studio/qwen-omni)为准。

图片闭环：React 工作台选择最多两张 PNG/JPEG → 同源 API 私有上传 → 解码和像素限制、重编码去 EXIF → 附件绑定固定聊天/知识库和幂等消息 → 模型以 `response_format: {"type":"json_object"}` 返回受限 JSON 观察 → 不确定编号先确认 → 原 AnswerService 路由普通回答或知识库检索 → 图片观察与原文引用分开显示。图片不自动入库，不作为知识库引用。默认问答关闭。

每张源文件 ≤10 MiB，解码后 ≤1600 万像素，宽高均 >10 像素且比例 ≤200:1。未发送附件 24 小时、已发送图片从上传起 30 天过期，且不超过聊天保留期。到期后聊天读取立即遮蔽该图片及后续派生回答；定时清理再移除文件、观察、关联回答及摘要。备份副本按备份保留周期到期，不能承诺即时擦除。图片只通过归属检查后的 `/api` 获取，不静态托管。上传后遇到模型故障会保存失败状态与安全原因，可重试或补充文字。模型观察需人工核对；低置信编号不能自动精确检索。

## 配置、兼容与数据影响

新增 `0008_image_attachments` **追加** `image_attachments` 和 `message_images` 表，不改旧消息数据。升级后旧 API 进程应停止，先停写并备份业务库、引擎库及私有运行目录，再对业务库显式执行 `cd backend; uv run --locked alembic upgrade head`，核对版本 `0008_image_attachments` 后重启唯一 API owner。**本轮没有迁移实际业务库，也没有重启旧业务服务；只重启本轮自建的 8001 独立验收 API**。旧数据库直接运行新 API 会因 schema 检查拒绝启动。若迁移失败，保持停写，从升级前完整备份恢复业务库与私有目录，并使用升级前代码；已有图片记录时迁移不允许直接降级丢失图片。不要在已有业务库上直接执行本轮测试。

图片沿用受控后端百炼北京空间凭证，不新增前端 Key。本轮两次合成图探测确认该空间可调用此型号，实际图片观察质量及完整问答仍待人工验收。依赖新增 Pillow（锁文件固定版本）用于真实解码和去元数据；Pillow 使用 HPND 许可。仓库默认问答关闭；独立验收服务单独启用，付费探测以单次授权为边界。自动化测试使用 `CITERAG_TEST_DATABASE_URL` 指向**独立空 PostgreSQL**，自动新建随机 schema，并使用合成图片与模型替身。

## 本轮自动化与人工验收

- 后端：存储拒绝损坏/伪扩展名/过小/极端比例图片、EXIF 清除；隔离 PostgreSQL 校验跨聊天不可读、回答绑定/重放、不确定编号确认、过期后的派生内容遮蔽。
- 前端：上传/确认/删除请求形状、页面交互与布局由 Vitest/浏览器合成样例检查；这些不证明新模型可用。
- 浏览器：用 Playwright 在既有 Vite 前端拦截 `/api`，仅注入显式标记的合成聊天/图片。1440px 桌面截图 `output/playwright/m3-desktop-1440-full.png`、390px 手机截图 `output/playwright/m3-mobile-390.png`、320px 窄屏截图 `output/playwright/m3-mobile-320.png` 已目视检查，无横向溢出；实际点开“添加图片”文件选择器，选择本仓库公开 Logo PNG 后看到待发送项，再点“移除”恢复。截图在忽略的 `output/` 目录，仅供本机复核，不随 Git 提交；页面中的红色铭牌和观察均为**浏览器合成响应**，不是真实模型结果。浏览器控制台无错误。
- 2026-09-28 图片失败诊断：独立验收库中的用户图片连续 3 次在图片观察阶段失败，历史错误码均为 `image_observation_unavailable`，无法区分供应商拒绝、格式和本地读取。未读取或重发用户图片。经本轮单独授权，使用公开合成 KX-17 PNG 对 `qwen3.8-omni-flash` 发起**恰好 2 次**探测：修复前 HTTP 成功但内容不是 JSON（总 Token 779），加入官方支持的 `json_object` 参数后 HTTP 成功，返回所需两个键且通过本地观察校验（总 Token 748）。未输出模型正文、凭证或请求标识。此证据证明该合成图的模型观察可用，不等于用户原图或完整问答链路通过。错误处理现按供应商权限、凭证、额度、限流、参数、网络、超时、协议、输出上限、格式和图片存储分别保存安全错误码；旧 `image_observation_unavailable` 保留兼容展示。相关官方说明：[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。
- 本次修复验证：独立空 PostgreSQL 上 M3 图片相关测试 16 项通过，含截断输出错误分类；前端 Vitest 226 项、typecheck、lint、build、相关 Ruff 和 `git diff --check` 通过。自建 8001 API 重启后健康接口返回 200。真实浏览器打开失败消息，在 1440、390、320 像素宽度下确认安全原因、错误代码与重试控件可见，均无页面横向溢出及控制台错误。**未点击用户原图重试**，因此用户原图识别、后续 AnswerService 路由和最终回答仍待人工验收。
- 真实图片问答仍待人工验收：在独立验收库主动上传清晰及模糊编号图片并提问；观察是否与可见内容一致、模糊时是否澄清、确认后是否只引用库内原文。两张图的问题须实际绑定两张附件。记录请求量、计费、型号、错误和证据，不上传凭证；旧失败消息可在服务更新后点“重试回答”。

## 下一切片建议

先完成用户在独立验收库的图片问答重试与观察质量判断，再按需求决定文件提问：PDF/DOCX/TXT/Markdown 已用于**知识库入库**，聊天临时文件需另定保留、解析、来源和是否入库语义。之后可做音频文件非实时理解，最后做视频抽帧/时间码与片段引用；每类均需单独控制大小、隐私、模型费用和来源结构。实时语音改用 Omni Realtime 属独立 M2 架构决策，不随图片型号自动替换。
