# M2 语音响应提速试用切片

2026-09-29；本切片在独立工作树 `D:\code\CiteRAG-voice-latency` 开发，未合入主工作树、未提交或推送。未调用真实 ASR、回答模型或 TTS，也未读取业务数据。本页描述待用户实测的行为，不能作为真人通话通过的证据。

## 行为

- ASR 最终转写后仍由原 `AnswerService` 自动路由并创建唯一持久提问。普通回答改用已有百炼回答模型的文本流；按稳定标点或最多 80 字切段，将首段立即送入现有 MiniMax HTTP TTS。模型后续生成与前段播报可重叠。
- 单次回答共用一条 LiveKit 输出轨道；每段 TTS 用当前已支持的 `speech-02-turbo` HTTP 接口，不假设 MiniMax WebSocket 对该模型兼容。分段可能增加 TTS 请求数、费用和段间停顿；后续需用实际计时和听感权衡。
- 语音页的“正在播报”仅在服务端开始送出该段 PCM 时追加文字。计时从最终转写到首段文字、首段音频送入 LiveKit；不是浏览器实际听见的时间。
- 知识库检索回答仍在来源和事实支持核验、持久提交后整段播报；不把未核验模型输出提前读出。文字问答及旧媒体入口继续走原路径。
- 插话、停止、纠错、挂断会撤销 generation，取消生成与分段 TTS，清空实际音频队列；迟到字幕被前端代际检查拒绝。TTS 失败保留已保存文字作为降级结果。

## 试用清单

在已确认归属的现有验收环境中启动此工作树版本；真实模型和真人音频仅由用户在已有授权范围内主动发起。本切片没有修改配置、数据库 schema、凭证或端口。

1. **普通交流**：说“你好，今天聊聊学习安排”。观察最终转写后是否先出现首段播报文字和音频，再逐段补全；记下“首段文字”和“首段音频送出”的服务端计时，并用真人听感另记“实际听见”的时刻。
2. **较长的普通问题**：问一个不涉及当前知识库的通用问题。核对没有伪造来源；比较整段完成前是否已有播报，注意段间停顿与音质。
3. **知识库问题**：问当前库可核对的资料事实。确认正式正文与来源仍在核验/保存后出现和播报；证据不足不提前播报未核验内容。
4. **插话与停止**：在第二段播报中说新问题或点“停止回答”。确认旧音轨立即停止、旧播报文字清空，后续不复活；新的最终转写才创建新提问。
5. **故障与恢复**：在可控验收环境模拟 TTS 失败。核对已保存文字仍可读，错误明确；挂断重连不重播旧音频，返回文字工作台可见记录。
6. **比较记录**：相同环境下各做三次短问候、长普通问答、知识库问题，记录最终转写→首段文字、最终转写→首段音频送出、真人听见、整段完成的中位数。分别记录 ASR 等待和模型路由耗时，不把服务端计时当成听感。

## 已做的离线检查

`backend/tests/test_voice_latency.py` 用合成模型片段和合成 MP3 检查提前播报、单轨输出、字幕随音频、插话取消、迟到事件与 TTS 失败文字降级；没有供应商调用。其他检查结果以交付时实际命令输出为准。

## 下一步判定

若首音频仍慢，先区分最终转写前的端点/VAD/ASR 时间，和最终转写后的路由、首段模型、TTS 时间。火山 ASR WebSocket 预连接或连接复用只有在官方协议、凭证生命周期和迟到事件隔离验证后再做；MiniMax WebSocket 也需先确认 `speech-02-turbo` 实际兼容。若分段 HTTP TTS 停顿明显，再评估兼容的流式 TTS，而不是盲目缩成“一个字一请求”。
