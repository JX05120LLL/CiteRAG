## 1 使用方式与本地数据边界

使用者打开本地工作台即可管理知识库、文档、聊天、附件和通话，并查看任务、配置状态和脱敏诊断。首版不提供账号、角色、注册、登录、密码管理、邀请、SSO、库/文档 ACL 或多用户功能。

同一本地安装使用一个服务端内部归属标识；不同浏览器访问同一份本地资料，不按浏览器创建“用户”。API 与前端仅在回环地址运行，不开放局域网或公网。访问本机操作系统和数据库的人员仍可能读取数据，本产品不提供对本机其他操作系统使用者的密码学隔离。

历史多用户实现的账号、会话及业务记录通过追加迁移保留，不自动认领、归并或开放。需要迁入旧资料时另行设计显式流程，不能因为移除登录而把历史资料全部显示出来。

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-A01 | 无登录直达工作台，自主管理自己的知识库 | 无管理员初始化、登录或账号管理入口；管理入口无需角色切换 |
| V1-A02 | 知识库、聊天、消息、附件、引用和房间检查本地归属及绑定 | 改写 ID 不得跨库、跨聊天或读取未归属的旧资料 |
| V1-A03 | 回环访问、Host/Origin 与跨站请求校验 | 远端请求、错误 Host/Origin 和伪造代理来源被拒绝；前端隐藏按钮不能替代服务端检查 |

## 2 首版闭环与范围

### 2.1 必须跑通的使用路径

1. 使用者直接进入本地工作台，创建自己的知识库，上传说明书或制度文件；系统检查、解析并交给 LightRAG 建索引。
2. 入库完成且检查通过后，库恢复“可问答”；用户选择该库新建聊天。
3. 用户文字提问，获得回答、来源文件与证据片段；可以查看原文。
4. 用户在同一聊天开始语音，系统识别、检索、回答并播放；用户插话后停止旧输出。
5. 用户挂断后上传铭牌或截图并提问；图片识别结果与知识库证据分别展示。
6. 刷新、重新打开浏览器或应用重启后，使用者仍可查看自己的聊天并继续提问。
7. 使用者更换/删除资料时，库进入维护；完成后新问答只使用当前资料，失败有修复入口。

首批样例以“产品说明与故障查询”为主，其他文本资料使用同一套能力。不开发表单式场景编排平台。

## 3 知识库与文档

### 3.1 文件范围与状态

首版支持 UTF-8 TXT、Markdown、可提取正文的文字 PDF，以及普通段落/简单表格的 DOCX。扫描 PDF、复杂跨页表格、XLSX、PPTX、旧 DOC、压缩包、加密或损坏文件不纳入 P0；给出转换提示，不把无法读取的文件显示成入库成功。图片提问的 P0 不等于批量扫描 PDF 入库也已支持。

初始限制：文件 20 MiB、单批 5 个、PDF 100 页。解析空白、乱码、正文顺序明显异常或表格对象关系不可靠时失败并要求修复源文件。当前受限解析最多 20 秒、384 MiB、500 万正文字符和 5 万定位块；普通 DOCX 不支持合并表格、嵌入对象、字段、修订或非空页眉页脚，拒绝后提示转换，避免静默漏失条件。首版不提供专门的人工发布审批页面。

文件状态：待处理 → 解析中 → 建索引中 → 可用 / 失败。  
库状态：empty → maintaining → ready；进入引擎修改后的失败/中断进入 blocked；删除完成进入 deleted。此前文件预检失败只使该任务失败，不影响已就绪库。

M1-2 页面分别展示“已受理”“解析完成/等待入库”“索引与来源核验通过”，不能用上传 202 或 SDK 返回值冒充成功。当前默认关闭模型入库，解析完成会持久等待。重建核验后才切换当前空间，旧空间隔离保留并显式提示待物理清理；这不代表删除/替换及旧空间清理已完成。

使用者在任务进行中看到“知识库维护中，暂不可问答”。同库一次只能修改一批资料，修改前结束该库正在生成的回答和通话。其他库是否可继续服务须通过隔离测试；未经验证不能宣称互不影响。

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-K01 | 建库、改名、列表、上传及任务进度 | 页面刷新不丢任务，上传成功不等于已能检索 |
| V1-K02 | 检查并保存原文和解析文本，调用 LightRAG 入库 | 完成状态以引擎实际文档状态和来源检查为准 |
| V1-K03 | 同库写操作互斥，维护时拒绝普通和精确问答 | 排空/取消旧轮次后再改索引，迟到结果不得发出 |
| V1-K04 | 删除、替换、失败重试及从原文重建 | 引擎修改失败或中断后保持 blocked，不能自动宣布旧索引完好；预检失败不封锁原就绪库 |
| V1-K05 | 知识库、引擎空间、原文来源一一可追溯 | 同名文件放在不同库时不串结果；同库相同内容提示重复 |

### 3.2 分块与来源

首版沿用选定 LightRAG SDK 的固定 token 入库路径，初始大小 1200、重叠 100；这是检索基线，不保证每个块都是 1200，也不保证语义完整。短文更短，末块可更短，长段落仍可能被截断。通过固定问题集检查关键条件丢失情况；需要更好的切分时在 P1 比较引擎的段落/递归策略，不再首版自行重写分块体系。

页面展示来源文件和证据片段。只有解析与映射确实得到页码/段落位置时才显示；无法可靠定位时显示“来源片段”，不编造页码。具体引擎输入、分块参数和映射规则见技术文档第 5 章。

### 3.3 修改后的历史行为

每次开始内容维护都递增库修订号。旧摘要失效，旧知识回答不作为新一轮的事实依据，重新查当前库；用户原始提问仍保留。

新增资料后，历史回答可显示为“基于旧资料”。删除、替换或不确定范围的重建后，首版保守遮蔽该库先前的知识回答与证据正文，显示“资料已变更，请重新提问”，避免实现复杂逐句失效逻辑。界面在管理操作前说明这一影响。

删除先禁止原文与引用访问，再清理引擎片段、向量、图、缓存和状态；失败保持库 blocked。不能只删除文档列表中的一行就声称已删除知识。

## 4 问答与精确查询

### 4.1 两条受控检索路径

普通解释性问题走 LightRAG 检索；明确要求文档编号、型号、版本等精确对象的问题，先走应用的等值查找和指定资料取证。两条路径共同经过会话归属、库状态、证据检查和最终回答模块。

2026-09-25 输入与意图澄清：工作台只保留一个提问框，由模型识别解释性问题、确认属性等值定位或知识库原文中的编号/短语字面定位，再由后端受控转发。订单号只是知识库精确查询的例子；模型选出的字面定位词必须逐字出现在问题中，后端只在当前库已入库原文中查找并核对完整边界与来源。多份资料命中时澄清，没有匹配时说明证据不足；不把 Top-K 过滤或虚构字段当作精确结果。路由结果随消息保存，重试沿用；旧 API 显式模式兼容。实时业务连接器仍不属于这条知识库查询路径。

2026-09-26 用户确认增加交流与资料问答分流：纯问候/致谢为普通交流；独立于私人资料的通用解释可不检索，页面标明“通用回答 · 未检索知识库”，不附知识库引用。涉及用户简历、项目、文档及其事实的介绍、总结、比较必须检索。路由读取本聊天近期上下文、已保存回答类型和有限资料名称，理解多轮指代；语义/通用追问可生成有长度限制的独立问题，精确条件仍受原候选和字面边界约束。知识库无结果不能转为通用回答补全私人事实；对象不明确时澄清。聊天仍固定一个知识库，沿用就绪、维护、修订和本地归属门禁，不提供联网搜索或跨库回答。

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-R01 | 一个聊天固定一个库，文字和语音共用问答规则 | 切库需新建聊天，不根据模型建议跨库 |
| V1-R02 | 真实调用 LightRAG 获取证据，并接入重排 | 调用模式、耗时、是否重排可查；不是只有配置开关 |
| V1-R03 | 固定文档属性等值筛选，指定资料取证 | A001 不匹配 A0010，001 不等于 1，X100 不等于 X100 Pro |
| V1-R04 | 回答返回正文、状态和可打开的证据来源 | 引用来自本轮实际证据，未映射来源不能包装成可信引用 |
| V1-R05 | 无证据、歧义、冲突和服务错误分开处理 | 超时不伪装成未找到；不足时澄清或说明限制 |

普通检索默认采用 LightRAG naive 模式 + 重排；首版的验收数据再决定是否需要调整。mix 作为受控效果对照，不能仅因为引擎支持就默认承诺更准确、更快。引擎默认入库可能仍做实体关系抽取，其成本独立于查询模式。

### 4.2 精确查询的首版边界

使用者可为资料填写并确认三个固定属性：文档编号 doc_code、型号 model_code、资料版本 edition。属性表示整份资料的适用范围；一份文件包含多个型号且不能明确标注时，不把其中某个型号填成全文件属性。

精确查找可按已确认属性确定资料，也可对问题中明确出现的编号/短语在当前知识库已入库的解析原文块中做有边界的字面定位。查询只返回有可核对原文位置的有限片段；多个资料命中、结果过多或超出扫描上限时询问缩小范围。不能先全库 LightRAG Top-K，再过滤成“精确结果”。

首版不自动理解任意表格字段，也不承诺未解析或跨块拆开的编号可查。知识库内的订单号、合同号等按原文字面定位处理，不等于接入实时业务订单系统。不同记录不能拼接成一条事实。

| 问题 | 首版行为 |
|---|---|
| “X100 的 2025 版说明书” | 文档属性等值定位，保留型号后缀和版本原值 |
| “查订单 ORD-001 的金额” | 在当前知识库的已入库原文块中完整字面定位 `ORD-001`；不误中 `ORD-0010`，引用实际原文位置 |
| “这份手册里的 E102 怎么处理” | 手册已确定时做完整编号字面定位；未确定先澄清 |
| “温度高后停机怎么办” | LightRAG 召回解释性片段，核查条件后回答 |
| “一共有多少订单” | 不对 Top-K 片段统计冒充全集；说明尚未提供该能力 |
| “我的订单到哪里了” | 若只指知识库资料而缺少具体编号，先请用户补充编号或资料；不猜用户身份或把旧文档当实时状态 |

### 4.3 回答形式

流式显示正文，旁边展示应用维护的来源列表；状态至少包含 answered、needs_clarification、insufficient_evidence、conflicting_evidence、failed、partial。引用标号由应用验证，模型不得自由生成 URL、页码或来源文件。

资料回答允许基于本轮真实证据忠实概括多个段落。正文与原文摘录分开：引用编号和摘录由应用确定性核对，概括正文再经独立模型事实支持检查；未经支持的事实、核验故障和引用不匹配分别报错，不展示为已完成回答。来源链接及页码由应用生成；正文中的资料网址必须实际出现在本轮已引用原文中。生成的总结缓冲到核验和持久保存完成后再分段展示，等待期间显示处理中；旧逐字摘录路径的 partial 记录和重试兼容保留。模型核验可能误判，不能以“引用存在”代替相关性、覆盖面和忠实性的人工与评测集验收。

语音播放可读正文，屏幕保留证据。图片观察与资料规定分别标明。数字、编号、单位及否定条件不能为了简短而删除。暂不强制模型逐句输出复杂 JSON 块，最终消息仍有稳定结构和状态。

## 5 聊天保存与上下文

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-C01 | 创建、命名、分页查看、继续和删除本人聊天 | 刷新、重新打开浏览器和重启后可继续，挂断不删除聊天 |
| V1-C02 | 用户输入先可靠保存，重复提交去重 | 已确认用户消息不因应用重启丢失；保存失败不显示成功 |
| V1-C03 | 助手回答记录完成、中断、失败与保存状态 | 流式临时尾部与已保存内容可区分，重试创建新 attempt |
| V1-C04 | 一聊天一次活动回答、一个语音控制端 | 不使用全局当前会话；冲突明确拒绝 |
| V1-C05 | 本会话近期窗口 + 简单摘要，按库修订号失效 | 不串聊天；摘要失败仍保留原文，可用近期窗口继续 |

完整记录保存在业务数据库。每轮只发送受预算约束的近期消息、必要摘要、当前问题和证据；LightRAG 不负责保存本产品的聊天。挂断不清空消息，同库的不同聊天不共享聊天记忆。

被打断的语音回答分别记录已生成文本和播放估计；没有播放确认的内容不能假定用户听过。库维护后，旧助手知识回答和摘要不自动参与新提示；用户引用“刚才那个”等不明确旧条件时需重新确认。

| ID | 首版需求 | 验收条件 |
|---|---|---|

## 7 页面与配置

首版四类页面：问答工作台、知识库与文档、任务详情、系统状态。打开应用直接进入工作台，没有登录、改密或账号管理页面。工作台参考 LiveRAG 的聊天区、选库入口、语音按钮和证据面板，使用原生 TypeScript 独立实现。

管理页面显示库 ready/maintaining/blocked、任务阶段、原因、重试/重建。没有发布审批、图谱编辑器、企业选择、通用场景设计器或复杂质量中心。

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-M01 | 一套本地安装级模型配置、能力测试和限额 | LLM/Embedding/重排/视觉/ASR/TTS 分别实测可用 |
| V1-M02 | Key 服务端保存，记录基本用量与错误 | 前端和日志无真实 Key，未知费用/用量不假装精确 |
| V1-M03 | 限制同时问答与入库，模型失败有限重试 | 满载有明确提示；已输出回答不无痕自动重放 |

高级参数写配置文件，系统状态页只查看和测试；在线模型配置编辑放 P1。字幕、键盘焦点、停止按钮与错误说明必须可用，不要求用户理解 chunk/token 才能提问。

## 8 数据与安全底线

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-S01 | 回环连接、Host/Origin/跨站校验、受限房间令牌 | 拒绝远端和伪造代理请求；不凭猜测 ID 访问文件或加入房间，业务和引擎存储不公开 |
| V1-S02 | 附件真实类型/大小/像素验证，解析资源受限 | 路径不能跳出存储目录；文档/模型输出不可执行任意动作 |
| V1-S03 | 删除、库维护和配置变更有脱敏记录 | 可定位本地操作与结果，保留期和清理失败可说明 |

| 数据 | P0 规则 |
|---|---|
| 原文、解析文本和引擎数据 | 保留至主动删除；维护/删除先停止使用，物理清理目标 24 小时内，失败保持不可查询 |
| 聊天、证据、摘要 | 最后一次已保存用户输入起 180 天；空聊天按创建时间；到期立即停止访问 |
| 图片及视觉解析结果 | 上传起 30 天，且不长于所属聊天；未提交的临时附件 24 小时 |
| 原始音频 | 默认不落盘 |
| 诊断/操作记录 | 30 天/180 天，脱敏轮转 |
| 备份 | 应用运行期间每日一次，滚动 7 天；错过计划下次启动补做，恢复前检查删除记录 |

清理由定时维护任务执行，在线副本目标 24 小时内移除；备份按其周期到期，不能宣称所有介质即时擦除。图片到期后也清理其派生观察并使相关摘要失效。

业务资料可能发送到已配置的模型服务，需列明各用途和处理地域；失败不自动转发到未配置供应商。提示词、文件、OCR/VLM 输出不是权限指令。用户只在主动提交反馈时授权附带所选问题与答案，不默认开放全部私人聊天。

## 9 本地运行边界

| ID | 首版需求 | 验收条件 |
|---|---|---|
| V1-O01 | 本地可复现配置、持久目录和健康检查 | 应用重启不丢已确认数据；API 固定单进程和单副本，所有浏览器入口绑定回环地址 |
| V1-O02 | 停机一致备份，至少一次空环境恢复 | 恢复业务库、原文和完整引擎数据，实际问答与引用可用 |
| V1-O03 | 故障可见，进程中断后的库与任务受控恢复 | 未确认的库保持 blocked；数据库不可写时不继续声称已保存 |

本机故障可能造成停机，备份可能丢失最近备份之后的数据；不承诺 99.9%、无损灾备或无缝升级。应用未运行期间不能承诺定时备份成功。恢复缺少最新删除证据时保持维护，核实后再开放。

### 10.2 初始样本与容量

初始评测至少 40 题：普通语义 15、支持范围内精确问题 10、无答案 10、资料变更/冲突 5；另有至少 20 段语音、10 张图片及 20 个归属/输入安全反例。开发与验收样本分开，记录模型、引擎提交、配置及期望来源。

容量候选：1 个本地使用者、5 个库、同一安装共 100 份文档或 10,000 个引擎片段；同时 1 路语音、2 路文字/图片生成、1 个入库/修改任务。并发上限用于约束同一使用者的多标签页，不能据此宣称支持多用户。任一上限达到后明确限制；实体图和原文件还受磁盘容量约束。更多并发属于后续压测扩容。

| 指标 | 初始验收目标 | 说明 |
|---|---|---|
| 越权/串库/已确认输入进程重启丢失 | 验收 0 例 | 任一可复现问题阻断试用 |
| 已确认精确属性与字面规则 | 固定反例全部正确 | 仅表示所支持规则正确，不代表任意自然语言百分之百正确 |
| 可回答题关键事实正确率 | ≥90% | 核对对象、数字、单位和必要条件 |
| 无答案题 | 10 题全部不编造 | 同时报告可回答题误拒答率，目标 ≤10% |
| 文字/语音有事实首响 | P95 ≤5 秒 | 含检索/模型/端点，提示“正在查询”不计；初始工程目标 |
| 插话至停止播放 | P95 ≤800 毫秒 | 同时报误打断与漏打断 |
| 混合负载成功率 | ≥95% | 限额内请求，超时和异常计失败，必须同时满足质量门槛 |

在目标本机和真实模型上至少测 50 次文字、50 次语音请求，记录硬件、网络、数据量及所有失败。上述是待测目标，不沿用此前自研检索的耗时假设；若不达标，应减少接纳负载或明确修改目标。

## 12 毕业设计专项与外部依赖

采用 LightRAG 能减少工程开发，但不能替代任务书中的音频预处理、特征提取、模型训练与调优。实验独立交付：合法数据、按说话人隔离的数据划分、预处理/声学特征、训练或微调脚本、配置与种子、指标曲线、失败分析和可复现记录。在线 ASR 可作基线，不可声称训练了不可访问的云模型。

具体训练对象由导师与算力条件决定；VAD 训练是否满足要求需导师确认。RAG 分块、naive/mix、重排与端点参数可以做消融实验，但不自动替代模型训练要求。

开发中逐步补齐：真实样例与预期问答；模型账号能力和处理地域；本机 PostgreSQL/pgvector、LiveKit 本地媒体连通性与备份目的地；预算；实验数据与算力。服务器和域名不是首版前置条件。Key 通过本地受控后端配置录入，不写文档或聊天正文。
