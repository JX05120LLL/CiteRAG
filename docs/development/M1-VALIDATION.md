## 2026-09-26 冷启动问答、输出截断与新版输入框对齐修复

### 根因与实现

- **冷启动失败已复现**：验收 API 重启后，首次自动问答在路由阶段抛出 `RuntimeError`，诊断确认模型客户端尚未初始化，未发送供应商请求。旧实现仅在打开 LightRAG 工作空间时创建客户端，而自动问答先执行意图路由。现在路由、普通回答、流式回答、摘要和引擎共用受锁保护的客户端初始化方法；首次问答独立初始化模型，启动时仍不读取模型凭证或调用供应商。每次入口检查运行状态和 API owner，关闭时统一释放客户端。
- **流式截断已复现**：真实简历问题的供应商 SSE 以 `finish_reason=length` 结束，触及现有每次 512 Token 输出上限；原代码误报 `answer_unavailable`。普通和流式回答现在将该原因映射为 `answer_output_limit`，页面说明生成达到长度上限并保留重试。部分正文继续保存为 `partial`，没有完整核验就不发布引用。
- 提示模型只逐字摘录最相关的短原文，建议最多 200 字符，为完整 JSON 留出空间；增加禁止改写的说明和正反例。回答模型使用 `temperature=0` 减少随机改写，参数依据为[百炼兼容 Chat API](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。仍严格核验原文跨度和引用 ID，不把改写结果冒充引用。引擎模型和摘要模型的采样参数未调整。短摘录提示不能保证模型每次遵循；不合格结果仍显示具体失败原因。
- 重复纯问候（如“你好你好”）直接返回补充问题提示，无知识引用；含具体问题的问候仍走正常路由。
- **新版样式覆盖了先前对齐规则**：1440 像素下输入框左边相对对话偏右约 78.4 像素，390 像素下左右各偏 4 像素。新版聊天列和输入框改用同一宽度、边距变量；首页布局保留。
