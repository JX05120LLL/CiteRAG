# M1-2 受管资料与任务实施计划

日期：2026-09-24。沿用 PRD 与技术架构第 5 章；本片不交付文字回答、删除/替换或完整 M1 验收。M0 超长 Embedding 边界继续暂缓未通过。用户已授权计划后直接实施；无 commit、push、部署或真实模型请求。

## 实施与验收

1. 追加 `0004_managed_ingestion`，保存 documents、parsed_blocks、ingestion_jobs、revision 和重建遮蔽水位。旧资料不认领、不清空；有新记录或空间切换时禁止 downgrade。隔离 PostgreSQL 验证升级、重复升级、失败事务与恢复。
2. 私有原文：服务端生成存储键，20 MiB/文件、5 文件/批；刷新文件后原子重命名，再提交受理任务。UTF-8 TXT/MD、文字 PDF（100 页）、普通 DOCX 在有时间与内存上限的子进程解析；保存实际行/页/段/表格行与字符范围。拒绝不支持或不可靠结构。
3. 单 owner 的持久队列：预检不修改库状态；同库上传/重建互斥，全安装串行引擎修改。进入索引前提交 maintaining 与 revision；引擎状态、原文、chunks 和实际检索来源核验通过才 ready。失败/中断后 blocked，显式重试或新空间重建；不自动重放不确定引擎写入。
4. 数据库 active_workspace 每次作为引擎选择依据；重建只在验证新空间后原子切换。旧空间隔离保留，清理状态单独记录，物理清理/删除替换完整验收属于 M1-4。
5. 前端保留 A 版与 Logo，区分受理/解析/入库核验；展示持久任务及错误和修复入口。网络故障手动同键重试，不存正文，不伪报成功。
6. 本机合成样本、数据库真实验证、LightRAG + 本地模型替身和真实浏览器，补基础 CI 冒烟；静态检查、diff 复核后同步 README/PRD/架构/路线/验证/交接。

## 风险与恢复

实际业务库只读核查为 `0002_local_single_user`，现有 API 无 M1-1 写接口；本片不迁移或重启它。隔离测试不使用真实业务/引擎库或凭证。以后升级前在停写窗口备份两库与原文；恢复保持维护并核对来源、任务与 active_workspace，不能只回退 schema。原文不通过静态目录公开，读取需本地归属及维护门禁。

模型入库默认关闭；解析完成后持久等待启用，不能显示入库成功。测试使用注入的本地替身，任何新供应商调用必须先单独获用户授权。旧五模型与真实双库证据只沿用。

重点反例：同键异载荷/同库同哈希、提交失败后的孤立原文、预检失败保留 ready、写入后失败保持 blocked、重启不自动重放、重建后重启不选旧空间、跨库伪造来源、库维护中的原文读取、文件类型伪装/ZIP 膨胀/解析超限。
