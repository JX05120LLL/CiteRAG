## 1. 所选设计方向

以当前问题和回答为中心，采用白色极简界面与轻量私人会话导航。来源靠近回答内联展开，用户可以按需核查；语音进入全屏模式，收起日常导航，以居中黑色声纹、字幕和底部浮动控制条聚焦通话。

图片沿用当前对话，组织附件预览、型号确认与知识库依据；知识库管理采用紧凑文件管理器，资料列表、上传与入库任务围绕同一操作组织。参考 LiveRAG 的全屏语音和浮动控制方式，产品范围仍按当前 PRD 执行。

| 页面 | 结构重点 |
|---|---|
| 问答工作台 | 对话为主，来源在回答附近内联展开 |
| 实时语音 | 白色全屏、居中声纹、字幕与底部浮动控制 |
| 图片提问 | 对话内展示附件、型号确认、观察与依据 |
| 知识库管理 | 紧凑文件管理器、清楚的入库阶段和修复入口 |

## 2. 视觉 tokens

纯白和黑灰构成主要层级，黑色集中于主操作与语音声纹。状态色只表达成功、警告和错误；阅读内容不依赖装饰性卡片制造层次。

| Token | 值 |
|---|---|
| 背景 / 柔和面 / 分隔线 | `#FFFFFF` / `#F5F5F4` / `#E4E4E4` |
| 正文 / 辅助文字 | `#171717` / `#666666` |
| 主操作 / 主操作文字 | `#191919` / `#FFFFFF` |
| 成功 / 警告 | `#32664D` / `#845E2B` |
| 错误 / 错误底 | `#A43B35` / `#FBEDEC` |
| 中文字体 | Microsoft YaHei UI / Microsoft YaHei / PingFang SC |
| 字号 | 标题 27 px；回答 16 px；说明 13 px；元数据 12 px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 px |
| 圆角 | 控件 20 px；输入区 24 px；面板 12 px；语音控制条 37 px |

按钮使用黑白主次层级，白底输入区保留明确边界；来源可内联展开。高频简单提问负担较轻；深入核查时可展开对应原文。参数来自 `a-design.json`。

## 3. 基础规范

- 基准尺寸 1440 × 960。审核器的缩放仅用于查看桌面稿，不表示已完成移动端产品布局。
- 基础中文字体栈：`Microsoft YaHei UI / Microsoft YaHei / PingFang SC / sans-serif`。中文正文以 16 px 左右、28–30 px 行高为阅读基准，界面 13–14 px，辅助和徽标 12 px；标题按内容层级调整，不依靠所有标题都放大来制造层次。
- 绘图基础采用线性 SVG 图标，常规 20 px、约 1.6 px 线宽。图标按钮必须有名称，图标与文字表达一致，不用 emoji 作结构图标。
- 间距以 4 / 8 / 12 / 16 / 24 / 32 / 48 px 为基本节奏；各页面根据任务调整区域比例，不能用不规则留白弥补信息结构问题。
- 控件采用上表的圆角规范：胶囊用于紧凑工具和语音控制，不将所有内容包成胶囊；内容面保持克制边线。阴影只帮助识别浮层。
- 主按钮只代表当前任务的主要下一步；次操作减弱。禁用同时给出原因。焦点可见，文字、图标和颜色共同说明状态。
- 输入框保留可见的上下文与范围。模糊型号必须能修改后确认；确认后的字段只读显示，重新修改需要返回确认流程。
- 型号后缀、编号、单位和否定条件不可为了排版而删减。引用靠近被支持的句子，选中引用应能找到对应原文。
- 中文正文目标对比度至少 4.5:1；焦点及关键可操作边界目标至少 3:1。淡分隔线只作区域组织，不单独承担交互提示。
- 动态仅服务状态变化；真正实现时遵循减少动态偏好。静态效果图中的声纹为演示，不代表音量、准确率或真实服务性能。

## 4. 四页验收点

| 页面 | 必须表达 |
|---|---|
| 问答工作台 | 私人会话入口、当前固定知识库、用户问题、回答、紧邻引用、可核查证据与原文入口、多模态提问、保存状态 |
| 实时语音 | 当前聊天与知识库、聆听/回答状态、字幕、可插话提示、静音、停止回答、挂断；通话中新文字/图片先挂断；已播放内容与保存状态一致 |
| 图片提问 | 本地聊天附件预览、型号观察与确认/修改、图片观察和知识库依据分开；不据模糊型号生成精确答案；附件不自动加入知识库 |
| 知识库管理 | 自有资料列表、上传入口、入库任务、维护对问答的影响、失败阶段与修复操作；直接可访问，无管理员身份；上传完成不等于入库成功 |

## 5. 状态设计规则

| 状态 | 呈现方式与下一步 |
|---|---|
| 空聊天 | 给出当前库与短提问引导；尚未选库时先选择库新建聊天；不放虚构的已有历史 |
| 空知识库 | 说明当前没有可问答资料，引导使用者管理自己的知识库；尚未实现的上传入口明确禁用并说明原因，不引导等待管理员 |
| 本地服务未配置 | 工作台仍可打开；明确说明数据库或模型未配置，状态页提供对应信息，不显示登录表单或虚构资料 |
| 查询 / 生成 | 显示可理解的阶段，如“查找资料 / 正在回答”；保留已输出内容和停止入口；临时尾部与已保存内容区分，不伪造百分比或耗时 |
| 无依据 | 明确“当前知识库依据不足”；保留问题，说明需要的型号或资料，邀请补充；没有证据不编造引用 |
| 待确认 | 把需要澄清的字段与原因放在当前任务中；允许修改；确认前不把猜测编号当作精确检索条件 |
| 依据冲突 | 标明资料存在不同说法，分别展示适用条件与来源，不强行拼成一条结论 |
| 服务失败 | 说明服务暂不可用，保留已保存输入和附件，允许明确重试；与“无依据”分开，不暗中重新生成整段内容 |
| 保存失败 | 持续显示“尚未保存”，保留当前可见内容，暂停新轮次；提供复制和重试保存，不能继续显示“已保存” |
| 中断 | 显示回答未完成；不将未播放、未保存的尾部计作已完成内容；停止回答不会自动挂断 |
| 语音聆听 | 中间字幕标为临时、尚未提交；上轮证据如保留，标明属于上轮，不能看似已针对当前未提交语音检索 |
| 语音回答 | 允许插话、停止与挂断；已播放句段对应已保存内容，余下正文仍可能生成中 |
| 语音失败 | 保留文字记录，允许重新接通或挂断转文字；不承诺断点续播旧音频 |
| 图片识别失败 | 保留附件与明确错误，允许补充文字或重试，不展示“识别成功”或空观察后继续宣称看懂 |
| 上传完成 | 只说明文件已接收，继续显示解析、索引和来源检查；全部通过后才可恢复问答 |
| 库维护中 | 暂停该库的新问答，结束当前回答与通话；任务期间禁用该库再次上传，显示禁用原因；任务说明当前阶段，允许离开后回来查看 |
| 入库失败待修复 | 进入索引修改后失败，库保持暂停；明确失败阶段、原因、重试或重建入口，不自动宣布旧索引完好 |
| 文件预检失败 | 只影响该文件任务；原就绪库可以保持可用，不能一律显示整库需修复 |
| 资料变更 | 新增后历史可标“基于旧资料”；删除/替换/不确定重建后遮蔽旧知识回答与证据，保留用户问题并提示重新提问 |

这里定义后续实现应遵循的状态语义；四张静态稿不等于全部业务行为已实现。

## 6. 产品边界

- 本地单用户，无管理员、注册、登录或角色切换；知识库管理和系统状态导航直接可见，不增加多用户、多企业切换或组织树。
- 一个聊天固定一个知识库。换库需要新建聊天；通话还需先挂断，不允许从模型建议自动跨库。
- 知识库、聊天、附件和引用归同一本地安装；不同浏览器使用同一份本地资料，旧账号资料不自动显示。
- 通话中的新文字/图片问题先挂断。转写纠错是专门操作，不是开放自由文本新问题。
- 图片提问不自动将图片或观察加入知识库；图片观察与资料事实明确区分。
- 资料更新期间暂停该库问答，结束现有回答与通话。上传完成、文件可用、库可问答是不同阶段。
- 资料支持 TXT、MD、文字 PDF、普通 DOCX；扫描 PDF 等不支持文件应明确提示，不伪装成入库成功。限额和保留期限沿用现有 PRD，不因设计稿自行扩展。
- 不增加实时订单连接器、图谱编辑、在线版本回滚、虚构准确率或性能仪表。界面默认不暴露 Embedding 型号、片段评分等对任务无帮助的技术细节。
- 只有可可靠映射的位置才显示页码；本轮没有真实资料来源，使用“来源片段”，不虚构精确页码。
- 所有用户、文件、型号、问题、答案和任务状态明确标为演示。
