# 交流分流、多轮路由与有依据的总结

2026-09-28 路由增量：正式 React 工作台与独立语音页共用 AnswerService。此增量仅用公开合成资料、隔离数据库和模型替身验证；没有读取私人资料、调用真实付费模型、迁移实际业务库或修改 schema。以下为当前规则；文末保留 2026-09-26 的历史验收边界。

## 路由和回答依据

| 一级决策／处理结果 | 保存的 route | 执行方式 | 页面说明 |
|---|---|---|---|
| 普通回答：问候、闲聊、通用知识 | `general` | qwen-flash 结合近期聊天上下文自然生成；无资料检索 | 普通回答 · 未检索知识库；无引用 |
| 知识库回答：普通语义检索 | `semantic` | LightRAG naive + 重排，回查本库受管原文，再生成和核验 | 知识库回答 · 语义检索；仅显示真实引用 |
| 知识库回答：确认属性等值定位 | `exact` | 只能选择当前问题命中的已确认候选属性；原取证门禁保持 | 知识库回答 · 精确检索 |
| 知识库回答：原文编号或短语定位 | `literal` | 定位词必须逐字出现在问题中，并在当前库原文中按完整边界核对 | 知识库回答 · 精确检索 |
| 指代或必要定位对象无法确定 | `needs_clarification` | 请用户补充对象、资料或编号，不猜测 | 需要澄清；无引用 |

路由模型接收最终文字问题（语音只在 ASR 最终转写后提交）、当前库名、至多 20 个就绪资料名称（每名最多 200 字符）、就绪资料数量、已确认属性候选，以及 revision/workspace 范围内的近期聊天。它按证据需求判断一级意图，不用“简历”“项目”等主题词作通用规则。同一问题可作通用回答、也与当前库资料相关时，优先尝试知识库；无证据仍返回证据不足，不改用常识。追问先看最近有实质内容的一轮；`semantic` / `general` 可输出最多 500 字符的指代改写，原提问完整保存。

普通回答器现在收到当前问题与受限近期上下文；历史只帮助理解指代和交流偏好。历史知识库轮次保留用户问题，但不把旧知识库回答正文交给普通回答模型；旧普通交流仍保留正文。先前 `chat` 固定寒暄分支已移除；新问候、闲聊和通用知识统一保存为 `general` 并由模型生成。旧 `chat` 记录仍能读取；旧失败记录重试时沿保存的路由调用普通回答模型。新路由结果不再产生 `chat` 或 `unsupported`，旧 `unsupported` 记录仍按原限制说明处理。

路由 JSON 和字段由应用检查，不执行任意工具、SQL、URL 或跨库操作。分类与问题改写仍可能出错，不能把结构有效当成意图准确。聊天继续固定一个知识库，所有消息沿用本地归属、知识库 ready、修订号及活动空间门禁；空库、维护和待修复阶段仍暂停发送。通用解释没有联网、时效核查或知识库事实保证。

## 总结与引用分开核验

模型的新内部输出：

```json
{
  "status": "answered",
  "text": "Nimbus 使用数据库保存数据，并用队列处理任务。",
  "evidence_ids": ["E1", "E2"],
  "support": [
    {"evidence_id": "E1", "quote": "Nimbus uses PostgreSQL."},
    {"evidence_id": "E2", "quote": "Nimbus queues work with Redis."}
  ]
}
```

示例为合成协议说明，不是验收资料。正文允许忠实改写、解释和多段整理；最多 1500 字符。引用最多 3 个本轮编号，support 最多 6 项，每项最多 600 字符；每个引用编号须有对应的非空连续原文摘录。未知编号、伪摘录、不完整 JSON、缺少对应摘录或凭空网址均拒绝。正文网址须与已引用证据中的完整 URL 匹配，不能拿 URL 前缀当成实际来源。页码、文件名、下载链接与引用 excerpt 均沿用应用回查的真实原文映射。

摘录核验通过后，再调用 qwen-flash 检查整段正文的数字、归属、条件、否定、因果与效果是否由所选证据支持；仅严格 JSON `{"supported":true}` 可进入原 ready/revision/workspace 提交门禁。拒绝显示 `answer_unsupported_claims`，核验格式或服务故障显示 `answer_verification_unavailable`；引用不符、输出截断和回答服务故障保留原安全分类。失败正文和引用不作为正式回答发布。模型原文、私人正文、Key、内部空间和供应商请求 ID 不写入公开诊断。

独立模型检查会增加请求、Token 费用和等待时间。它仍可能误判，尤其同模型生成与核验可能产生相关错误；真实引用存在不能证明所有总结事实正确。相关性、遗漏、错误归属和过度推断须继续用真实评测集和人工检查。

## SSE、历史与兼容性

新总结在模型生成时缓冲；来源和支持核验完成、数据库提交后，沿现有 SSE 分段展示 `saved=true` 正文并发送 `saved` 与正式引用。期间显示“正在识别问题并准备回答”，不冒充已核验的首响。旧无 support 的模型输出仅兼容一条证据的逐字连续摘录，不能绕过总结核验。已有 partial 持久记录及 failed/interrupted/partial 重试守卫保留。

现有普通、流式、重试、语音最终转写和历史接口，以及旧显式 semantic/exact 请求继续使用；路由仍保存在现有消息 JSON 中，没有数据库迁移或公共 API 变更。输出上限保留：普通回答 1024、路由 384、资料回答 2048、支持核验 128 Token。2026-09-29 起输入改按保守 Token 估算门禁，路由约 3000、普通约 4000、知识库回答约 10000，其中原文约 4000、有效历史约 2000；不再使用这些请求的旧字符数门禁。完整预算、批量摘要触发及隔离比较见 [Token 预算验证](CONTEXT-TOKEN-BUDGET-VALIDATION.md)。这些阈值不是最优结论，真实费用和质量待测。

## 控件与接口

| 控件 | 实际方法／接口 | 行为 |
|---|---|---|
| 单输入框、发送问题、Enter | `sendChat` → `POST /api/conversations/{id}/messages/stream`，`mode=auto` | 自动分流，处理中不可重复发送 |
| 重试回答 | `retryChat` → `POST /api/conversations/{id}/messages/{id}/retry` | 新 attempt，保留旧尝试，沿用保存路由 |
| 聊天历史 | `GET /api/conversations/{id}/messages` | 读取持久状态及依据类型；未核验来源不显示 |
| 引用按钮、关闭来源 | 当前已保存 citation 的来源详情 | 应用生成真实文件与定位，关闭仅改变视图 |
| 下载原文 | `GET /api/documents/{id}/original` | 原本真实下载入口；本轮未点击下载，不标为新验证通过 |
| 添加图片 | 明确禁用并说明未接入 | 本轮没有伪造图片问答 |

真实 Chromium 浏览器在全部 `/api/` 请求拦截为合成响应的独立会话中，点击合成知识库与聊天，看到普通回答无引用、语义检索的明确证据不足、精确检索的来源入口；320px 无横向溢出。截图仅在忽略目录 `.local/intent-router-20260928/route-text-{1440,390,320}.png`；语音页 320px 仅检查未通话布局和初始状态，没有触发麦克风、供应商或假通话。没有使用私人资料或本机验收业务库。真实模型对不同主题库的判断、回答质量、Token 成本，以及真人 ASR 最终转写和听感均待用户集中验收。

集中验收步骤：

1. 打开并刷新 `http://127.0.0.1:5173`，进入现有验收聊天。
2. 输入问候或致谢，再问一个与当前库无关的通用问题；检查两次普通回答有自然变化、带“普通回答 · 未检索知识库”标签且没有引用。
3. 在不同主题的知识库各问一个通用概念，再追问“它有什么优点”；核对上下文衔接，避免误用更早的资料话题。
4. 对当前库已就绪资料提出总结和后续追问；两轮应显示知识库语义检索，点击引用核查原文中的数字、归属、条件和遗漏。问题也可通用解释但当前库相关时，先尝试知识库。
5. 使用资料中实际存在的编号提问，检查精确检索和原文位置；对象不明、多个对象或无依据时应澄清或提示证据不足，不自动改为通用知识补齐。
6. 在同一聊天用真人语音说出上述问候、通用问题和资料追问，确认最终转写后才保存提问、路由与文字一致；核查播报、引用、打断和重连。此项尚未在本轮执行。
7. 窄屏检查输入区边界、来源详情的打开／关闭和长文本换行。若失败，核对安全错误码并重试；任务和旧失败尝试继续保留。
