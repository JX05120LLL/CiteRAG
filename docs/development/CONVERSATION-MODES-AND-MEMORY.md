# 固定聊天类型与同库共享摘要

2026-09-30 的源码切片；下述自动验证只使用隔离 PostgreSQL、合成资料和模型替身。实际业务库尚未迁移，真实模型与真人语音效果未在本切片验收。

## 行为与边界

| 聊天绑定 | 服务端处理 | 上下文 | 来源 |
| --- | --- | --- | --- |
| `kb_id: null` 普通聊天 | 直接调用现有 `general_answer`；不调用库意图路由、LightRAG 或知识库检索 | 仅本聊天近期记录与本聊天摘要 | 不生成知识库引用；即使提到库名也不越界 |
| 固定 `kb_id` 知识库聊天 | 保留普通回答／知识库回答路由；知识库回答再走精确或语义检索 | 本聊天上下文，加至多 4 条当前库的有效共享摘要 | 资料回答仍由当前库原文支持并核验 |

创建时必须显式给出 `kb_id`，值为 `null` 或本人已有知识库 ID。创建后不能切换类型或库；另建聊天。文字、语音最终转写、图片观察后提问及失败重试共用 `AnswerService`。普通聊天使用内部 `workspace=ordinary, revision=0` 表示无库，不将其当作真实知识库空间。旧聊天的非空 `kb_id` 保持不变。知识库聊天仍受库就绪、维护、修订和活动空间门禁控制。

## 共享摘要

用户可从**同库当前修订中已有成功回答的一条纯文字提问**手动提炼短偏好或持续讨论背景；这不是模型自动抽取。每条最多 300 字，每库最多 20 条，单轮最多读取最近 4 条；输入整体仍受现有模型 Token 预算约束。图片消息不能作来源，避免图片到期后把视觉内容留在共享摘要。列表显示来源聊天／消息、类别、生成时间与有效状态，允许删除。摘要是提示上下文，不是证据；资料事实必须重新查询当前库并核验原文。

`knowledge_memories` 记录本地归属、库、来源聊天／消息、类别、内容、创建时间、库修订和活动空间。读取时检查归属、来源聊天仍可访问、库就绪、修订和空间完全匹配。删除来源聊天或 180 天到期清理时物理删除其共享摘要；资料删除／替换或库重建造成修订或空间变化时，旧条目保留为**已失效**供查看和删除，但不进入提示。普通聊天及其他库永远不读取该表。当前没有独立删除单条原始消息的 API。

`GET /api/knowledge-bases/{kb_id}/memories` 查看；`POST` 接收 `source_message_id`、`kind` 与 `content`；`DELETE /{memory_id}` 删除。三个入口都检查本地归属。前端「同库共享摘要」只在知识库聊天提供，并调用这些接口。

## 保留、迁移与恢复

普通聊天及其原文和本聊天摘要现在保留至使用者主动删除；知识库聊天仍是最后已保存用户输入起 180 天（空聊天按创建时间），到期停止访问并由定时任务清理。**图片仍按原有 30 天及所属聊天上限**；诊断、备份期限不变。主动删除先清理相关图片、共享摘要、回答、消息和本聊天摘要；备份按原有周期轮转，不能宣称从备份即时抹除。

业务库 schema 从 `0009_conversation_archive` 升至 `0010_conversation_modes_memory`：仅将 `conversations.kb_id` 改为可空，并新增共享摘要表及索引；旧非空绑定不重写。公共创建协议要求显式 `kb_id`，响应可返回 `null`；老客户端若省略字段会收到 422，需升级前端。旧客户端传非空库 ID 的行为不变。降级只有**不存在普通聊天及共享摘要**时才允许；否则拒绝，避免丢失数据。

实际业务库操作需另获授权：先停写并关闭唯一 API，备份**业务库、LightRAG 引擎库、私有原文／图片目录和受控配置**；记录当前 Alembic 版本与恢复点，确认整套恢复演练，再显式升级和重启。回滚优先恢复同一时点的完整备份；不可只回退 schema 而保留新记录。本切片只在独立临时数据库验证，不触碰实际业务库。

## 未来共用工具网关的接口边界

本切片不执行 MCP 或外部写入。后续工具调用应由服务端在确定聊天绑定后构建作用域：`conversation_id`、本地归属、可选 `kb_id`、工具 ID、目标与参数、读／写权限和请求幂等键。普通聊天默认没有知识库读取权限；工具即使声明可读，也必须拒绝越界库 ID。敏感写入先把目标、参数、影响展示给使用者，取得与本次调用绑定的确认后再执行。工具结果应记录工具名、目标、状态及错误，与已核验的知识库引用分开呈现；失败不能伪装成功或偷偷改走其他工具。上述授权协议和结果结构尚未实现，接入时需单独审查公共协议。
