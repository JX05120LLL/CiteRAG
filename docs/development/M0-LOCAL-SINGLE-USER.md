# M0 本地单用户范围调整与实施计划

依据：2026-09-22 用户明确修正首版为本地单用户，不需要管理员，由使用者管理自己的知识库。本决定替代旧文档中的单企业、admin/user、账号分配与登录要求。

## 设计与边界

- 浏览器直接进入本地工作台；没有注册、登录、管理员、密码或账号管理流程。
- 同一安装使用一个内部本地归属标识，知识库、聊天及以后实现的附件均归该标识。它不是可登录账号，不授予管理员角色；不同浏览器使用同一本地资料。
- API 和 Vite 仅用于回环地址，Uvicorn 使用 `--no-proxy-headers`。API 检查连接地址、Host、Origin 与跨站请求，拒绝 `Forwarded` / `X-Forwarded-*`；无登录不代表允许局域网或公网访问。不能信任代理传来的任意身份。
- 保留原生 TypeScript、Vite、FastAPI、PostgreSQL、固定 LightRAG 和后续 LiveKit。没有切换 SQLite，也不接入真实模型。
- 业务数据库仍需显式创建和迁移。无数据库时工作台可打开，状态明确显示未配置，数据库相关列表返回可辨识的 503；不显示模拟资料或登录表单。
- 旧迁移 `0001_m0_accounts` 不改写。新增迁移建立本地归属，给知识库及聊天添加本地归属列，旧聊天账号外键列保留且允许新本地聊天不填写。已有账号、会话和业务记录保留；旧多用户资料不自动归并、不自动开放。
- 本轮只修正 M0 基础。知识库管理入口可直接访问；建库、上传、入库、问答仍按后续门槛开放，不把入口可见视为功能已完成。
- 保留 A 版布局和「回响」Logo，改正团队、管理员和登录相关文字。四张设计导出图保留为历史布局参考，文案差异在设计说明标注。

## 接口约定

- `GET /api/health`：进程存活及数据库是否配置，保留现有结构。
- `GET /api/status`：`status`, `mode: local_single_user`, `database`, `rag`, `models`；无数据库也可返回明确状态，不返回连接信息。
- `GET /api/knowledge-bases`：当前本地归属下的全部库状态，保留 `{items: [...]}` 结构。
- `GET/POST /api/conversations` 与 `GET /api/conversations/{id}`：只使用服务端本地归属；建聊天仍要求该归属下的库已 ready。
- 移除 `/api/auth/*`、`/api/me`、`/api/admin/*` 及管理员初始化 CLI 的有效入口。

- [x] 集成：运行后端测试/lint、前端测试/类型检查/构建和仓库检查；浏览器检查 1440×960 工作台、知识库页与窄屏。
- [x] 记录：区分隔离数据库真实验证、前端模拟响应验证与未完成的模型/知识引擎验证；M0 继续标记未通过。

结果与边界详见 [M0 验证记录](M0-VALIDATION.md)：本轮范围修订通过，M0 真实接入仍有缺项。

重点回归：旧数据不得意外公开；缺配置不能显示就绪；远端 Host/Origin 不能读取本地资料；数据库不可写不能伪报成功；重复迁移不能产生多个本地归属。

全部更改保留在本地工作区，不提交、不推送、不部署。此次不访问用户现有数据库、不读取真实凭证。
