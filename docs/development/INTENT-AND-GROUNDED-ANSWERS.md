# 交流分流、多轮路由与有依据的总结

日期：2026-09-26。用户确认的改进已实现于原生 TypeScript/Vite、FastAPI 和现有 LightRAG 路径。入库、问答默认关闭；本轮真实测试沿用用户对独立验收环境的持续模型授权，未设置请求次数上限。未改数据库 schema、迁移实际业务库、部署、提交或推送。

## 路由和回答依据

| 提问类别 | 保存的 route | 执行方式 | 页面依据说明 |
|---|---|---|---|
| 纯问候、致谢 | `chat` | 本地完整礼貌消息规则，不调用供应商或检索 | 普通交流，无引用 |
| 其他普通交流 | `chat` | 路由选择后返回本地能力介绍 | 普通交流，无引用 |
| 通用概念解释 | `general` | qwen-flash 回答独立问题，不向回答器发送资料证据 | 通用回答 · 未检索知识库，无引用 |
| 用户资料的介绍、总结、比较、事实追问 | `semantic` | LightRAG naive + 重排，回查本库受管原文，再生成和核验 | 已保存并核验，显示实际引用 |
| 确认属性等值定位 | `exact` | 原候选 ID、文档属性与取证门禁保持 | 实际来源，不跨库 |
| 原文编号或短语定位 | `literal` | 定位词仍须在当前问题中逐字出现，保持完整编号边界 | 实际来源，多份资料命中时澄清 |
| 指代不清或范围不明确 | `needs_clarification` | 请用户说明具体资料或对象 | 需要澄清 |
| 全集统计等未接能力 | `unsupported` | 说明能力限制 | 当前不可查询 |

路由模型接收当前问题、最多 20 个就绪资料名称（每名最多 200 字符）、已确认属性候选和 revision/workspace 范围内的短上下文。近期自动问答增加来自已保存路由的 `answer_kind`；路由优先跟随最新实质话题并跳过纯交流。`semantic` / `general` 可输出最多 500 字符的独立问题改写，原提问仍完整保存。语义路径使用改写检索，通用回答器仅收到独立问题；历史用于理解指代，不能代替本轮资料证据。

路由 JSON 和字段由应用检查，不执行任意工具、SQL、URL 或跨库操作。分类与问题改写仍可能出错，不能把结构有效当成意图准确。聊天继续固定一个知识库，所有消息沿用本地归属、知识库 ready、修订号及活动空间门禁；空库、维护和待修复阶段仍暂停发送。通用解释没有联网、时效核查或知识库事实保证。

## 总结与引用分开核验

模型的新内部输出：

```json
{
  "status": "answered",
  "text": "Nimbus 使用数据库保存数据，并用队列处理任务。",
  "evidence_ids": ["E1", "E2"],
  "support": [
    {"evidence_id": "E1", "quote": "Nimbus uses PostgreSQL."},
    {"evidence_id": "E2", "quote": "Nimbus queues work with Redis."}
  ]
}
```

示例为合成协议说明，不是验收资料。正文允许忠实改写、解释和多段整理；最多 1500 字符。引用最多 3 个本轮编号，support 最多 6 项，每项最多 600 字符；每个引用编号须有对应的非空连续原文摘录。未知编号、伪摘录、不完整 JSON、缺少对应摘录或凭空网址均拒绝。正文网址须与已引用证据中的完整 URL 匹配，不能拿 URL 前缀当成实际来源。页码、文件名、下载链接与引用 excerpt 均沿用应用回查的真实原文映射。

摘录核验通过后，再调用 qwen-flash 检查整段正文的数字、归属、条件、否定、因果与效果是否由所选证据支持；仅严格 JSON `{"supported":true}` 可进入原 ready/revision/workspace 提交门禁。拒绝显示 `answer_unsupported_claims`，核验格式或服务故障显示 `answer_verification_unavailable`；引用不符、输出截断和回答服务故障保留原安全分类。失败正文和引用不作为正式回答发布。模型原文、私人正文、Key、内部空间和供应商请求 ID 不写入公开诊断。

独立模型检查会增加请求、Token 费用和等待时间。它仍可能误判，尤其同模型生成与核验可能产生相关错误；真实引用存在不能证明所有总结事实正确。相关性、遗漏、错误归属和过度推断须继续用真实评测集和人工检查。

## SSE、历史与兼容性

新总结在模型生成时缓冲；来源和支持核验完成、数据库提交后，沿现有 SSE 分段展示 `saved=true` 正文并发送 `saved` 与正式引用。期间显示“正在识别问题并准备回答”，不冒充已核验的首响。旧无 support 的模型输出仅兼容一条证据的逐字连续摘录，不能绕过总结核验。已有 partial 持久记录及 failed/interrupted/partial 重试守卫保留。

现有普通、流式、重试和历史接口及旧显式 semantic/exact 请求继续使用；route 新增 chat/general，须使用匹配版本前端读取。路由改写保存在现有消息 JSON 中，重试沿用保存路由，没有数据库迁移。回答单次输出预算 2048 Token、通用回答 1024、路由 384、支持核验 128；引擎和历史摘要客户端上限保持 512。输出预算与持续测试的请求次数是两个独立配置。

## 控件与接口

| 控件 | 实际方法／接口 | 行为 |
|---|---|---|
| 单输入框、发送问题、Enter | `sendChat` → `POST /api/conversations/{id}/messages/stream`，`mode=auto` | 自动分流，处理中不可重复发送 |
| 重试回答 | `retryChat` → `POST /api/conversations/{id}/messages/{id}/retry` | 新 attempt，保留旧尝试，沿用保存路由 |
| 聊天历史 | `GET /api/conversations/{id}/messages` | 读取持久状态及依据类型；未核验来源不显示 |
| 引用按钮、关闭来源 | 当前已保存 citation 的来源详情 | 应用生成真实文件与定位，关闭仅改变视图 |
| 下载原文 | `GET /api/documents/{id}/original` | 原本真实下载入口；本轮未点击下载，不标为新验证通过 |
| 添加图片 | 明确禁用并说明未接入 | 本轮没有伪造图片问答 |

工程与真实结果见 [M1 验证记录](M1-VALIDATION.md)。新增测试进入已有 CI 测试文件，未触发或声称远端 GitHub CI 已运行。自动化使用临时 PostgreSQL、合成资料和模型替身；供应商 HTTP 测试使用 MockTransport，不能替代真实模型验收。

本机真实截图含私人资料，仅保留于忽略目录 `.local/intent-summary-20260926/`：`project-{1440,390,320}.png`、`source-{1440,390}.png`、`general-{1440,390,320}.png`。没有公开私人资料或截图。

集中验收步骤：

1. 打开并刷新 `http://127.0.0.1:5173`，进入现有验收聊天。
2. 输入问候或致谢，检查“普通交流”、适当礼貌回复和无引用。
3. 提问通用概念，再问“这个概念有什么优点”；两轮应显示“通用回答 · 未检索知识库”，没有资料引用。
4. 介绍当前资料中的项目，再问“这个项目主要用什么技术”；两轮应返回与该项目相关的内容，点击引用核查原文中的数字、归属、条件和遗漏。
5. 使用资料中实际存在的编号提问；对象不明、多个对象或无依据时应澄清或提示证据不足，不自动改为通用知识补齐。
6. 窄屏检查输入区边界、来源详情的打开／关闭和长文本换行。若失败，核对安全错误码并重试；任务和旧失败尝试继续保留。
