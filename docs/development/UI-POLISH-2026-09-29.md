# 对话优先界面细化（2026-09-29）

本轮依据用户确认的桌面图例整理正式 React 工作台、知识库、资料、任务、状态和独立语音入口。图例与浏览器中的合成资料只用于检查排版和操作状态，不作为实际业务或模型验收。

## 交互边界

- 对话在左侧按知识库分组；侧栏菜单中的重命名、删除、归档均调用原有控制器或新增归档接口。归档列表按需读取并可恢复；归档不删除记录，也不延长现有 180 天保留期限。
- 归档对话保留历史读取；新文字问答、重试、图片写入及新语音通话由服务端拒绝。正在回答或通话中不能归档。归档及恢复只作用于本地归属的对话。
- 来源只在已保存且可显示的知识库回答下出现；点击后读取当前消息的已核验摘录。普通回答没有来源入口。
- 语音页把通话控制、临时字幕和同一聊天的已保存问答分开呈现。页面打开不连接媒体；ASR 最终转写和回答仍沿用现有 VoiceController/AnswerService，不另存一套语音历史。
- 资料、任务和状态只重排现有真实接口数据；不可执行的维护操作继续禁用。系统状态显示配置与验证的区别。

## 归档兼容与数据影响

新增 `0009_conversation_archive`：`conversations.archived_at` 可为空，并新增本地归属与归档时间索引。旧数据为空，默认仍在活跃列表。`GET /api/conversations` 增加可选 `archived=true`（默认只列活跃对话），`PATCH /api/conversations/{id}/archive` 接收 `{ "archived": true|false }`；`ConversationView` 增加可为空的 `archived_at`。旧客户端的创建、读取、改名、删除接口保持可用。归档后仍可按 ID 读取历史。

迁移只允许在停写、备份并确认恢复方式后用于实际业务库；本轮不迁移实际业务库。回滚 `0009` 会丢失归档状态并让这些聊天重新出现在活跃列表，因此回滚前须先导出或确认可放弃归档标记。新后端代码需要 `0009` 后才能连接对应业务库。

## 验证分层

前端 Vitest、类型检查、lint 和构建核对组件与协议；后端单元检查、Ruff、编译核对路由和服务。浏览器使用 `output/ui-polish/` 中明确标注的合成 API 拦截脚本，禁止写请求。截图仅证明页面布局和只读交互。归档及迁移在随机本机端口的临时 PostgreSQL 16 容器运行了 `test_postgres_local.py` 与 `test_m13_answer_api.py`，结果 25 passed；其中从 `0008` 升级的用例确认旧聊天保留且默认为未归档。测试建立独立 schema，未接触实际业务库。实际业务库迁移、真实模型/语音和真人设备不在本轮验收内。

## 桌面图例二次对齐

根据用户指出的图例与实现偏差，正式页面再次调整：侧栏使用完整导航与按知识库分组的对话；顶部把当前知识库选择和状态放在同一区域；工作台使用单层回答卡、时间、头像和卡内来源按钮；知识库改为双列大卡；资料页改为上传条、状态列与行级更多菜单；任务页同时展示真实统计、分页列表和内联详情；状态页改为四张能力卡与模型、备份面板；语音页保留简明通话控制，并在同一页展示当前聊天记录。来源详情抽屉使用真实已保存的摘录、定位和下载地址。示例图中的数量、回答、来源和通话成功状态没有写入正式页面。

`StateTag(empty)` 显示“暂无可问答资料”，用于区分受理或解析完成与真正入库。资料列表仍显示单份资料的实际阶段，任务列表仍显示后端保存的失败原因。任务统计的“进行中”“需要处理”“已结束”分别来自 `active_items.length`、`failed_count`、`total`，不把历史失败覆盖为成功。

2026-09-29 的本机视觉复查使用 1484px 浏览器及合成只读 API 拦截，不调用模型、不执行写操作；截图保存在本机忽略目录 `output/ui-polish/`。另在独立 PostgreSQL 17 容器 `citerag-ui-review-20260929`、独立 API 8001 与前端 5175 上，通过真实页面控件创建“UI隔离验收知识库（无模型）”并上传一份合成 TXT；入库开关关闭，真实任务仅解析完成，问答仍不可用。这只证明隔离库页面与资料接口接线，不代表实际业务库、模型或语音验收。

## 侧栏、色彩与隔离库手动验收续接

用户随后指出正式页面的导航图标与文字错位、状态颜色不一致，并要求实际聊天和通话。导航行现将图标、文字垂直居中；知识库分组长名称单行截断并保留完整标题，聊天标题从图标后左对齐。正式 React 主题统一深蓝正文、绿色可用状态、琥珀色待验证状态和红色故障状态。语音尚未开始时显示“助手连接待验证”，不能把闲置态写成“助手已停止”。这些改动不改变 API 或聊天归属。

经本轮单独授权，原隔离库中的公开合成 TXT 在至多 20 次百炼请求的受控会话中自动继续入库；服务端返回知识库 `ready`、任务 `succeeded / complete`、“入库与来源核验通过”。随后切换为常规手动验收服务，隔离业务 PostgreSQL 仍为 55434，前端 5175、API 8001、本机 LiveKit 7880/7881。知识引擎使用现有 55433 引擎数据库的**新知识库 UUID 工作空间**；合成入库在该空间产生数据，未迁移实际业务库或访问其他知识库正文。隔离库更名为“UI隔离验收知识库（合成资料）”，并通过真实页面建立一个空聊天，未代用户发送问答或开始麦克风通话。

后端 `/api/voice/status` 返回 transport 与 assistant 均为 `configured`；页面的“开始语音通话”可点击，尚待真人权限、ASR、回答、TTS 和播放验收。状态页 models/rag 仍显示 `unverified`，这是全局验证记录的状态，不能以单份合成资料入库替代完整模型或引擎验收。受保护的供应商凭证未输出或写入前端；临时本地 LiveKit 会话凭据仅保存在被 Git 忽略的 `.local/ui-review-20260929/`。手动验收可能产生供应商费用，页面打开本身不发起请求。
