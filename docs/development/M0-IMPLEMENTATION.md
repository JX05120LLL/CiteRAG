## 范围与验收

1. **工程与页面壳**：保留 `frontend/` 原生 TypeScript/Vite/pnpm 和 `backend/` Python 3.12/FastAPI/uv 工程及锁文件。沿用无字回响 Logo、72 px 顶栏、232 px 聊天侧栏、白色内容区与底部输入区。直接进入本地工作台，无登录、管理员或角色切换；知识库管理导航可访问。前端构建、类型检查及状态测试通过，浏览器核对 1440 × 960 与窄屏。
2. **本地归属与业务库**：保留 PostgreSQL，SQLAlchemy/Alembic 只管理业务库；显式迁移，不在启动时自动建表。追加迁移建立内部本地归属并扩展库与聊天；旧账号、会话和业务记录保留，不自动认领或公开。使用独立临时 PostgreSQL 验证新库、旧库升级、重复迁移与资源筛选。
3. **本地请求边界**：API 与前端绑定回环地址，校验连接来源、Host、Origin 与跨站请求，拒绝伪造代理头。旧登录、管理员 API 与初始化命令退出有效入口；无数据库也可打开工作台，业务接口明确不可用。
4. **引擎基础门禁**：固定 LightRAG 提交 `59af311307c7417b342f44850b097648d47e83bd`；按库 UUID 生成 workspace/工作目录，拒绝全局覆盖。EngineManager 管理初始化/关闭与并发获取；API 独占 PostgreSQL advisory lock，失锁停止受理并退出。契约测试与真实 PostgreSQL 测试分开记录。
5. **交接证据**：同步运行说明与 M0 结果，列出真实 PG 四类存储、两库检索隔离、Embedding 输入上限/维度、重排、来源映射和模型失败路径的待测条件。模拟对象仅验证应用契约，不算真实引擎通过。

## 影响范围

- 从浏览器移除账号与登录流程，所有本地浏览器使用同一安装的资料；不扩展局域网或公网访问。
- 追加迁移兼容旧数据，不改写历史迁移，不删除旧账号记录，不在此次升级中迁入旧资料。数据库访问仍需要 PostgreSQL 连接凭证，它与网页账号无关。
- 配置只从受控后端进程环境读取，不自动读取 `.env` 或现有凭证文件；连接串不写源码、文档或聊天。
- 保留架构已指定的构建、API、持久化、迁移和测试工具；LightRAG 为可选安装组，打开工作台无需加载 SDK 或调用模型。不额外引入新框架。
- 本机现有 PostgreSQL 服务保持原状；测试使用项目 `output/` 中新建的隔离集群、独立端口和随机测试凭证，结束后停止。
- 语音、图片、建库入库和回答生成仍按后续阶段开放；本轮只调整 M0，不推进 M1/M2/M3。

## 核对重点

- 无登录直达工作台；未配置数据库、连接故障与引擎未接入分别呈现，不伪报 ready。
- 本地归属由服务端确定，客户端不能改写 owner 读取旧账号资料；聊天仍固定已就绪且同归属的知识库。
- 非回环连接、错误 Host/Origin、跨站请求与代理伪造来源被拒绝。
- 新库迁移与旧库升级均可验证；旧记录保留且默认不可见，重复迁移不会增加多个本地归属。
- 第二个 API owner 被拒绝，锁连接丢失后不能继续返回成功。
- 初始化失败不缓存半初始化引擎；关闭失败仍清理其他实例；路径不能脱离受控根目录。
- 前端无虚构历史、引用或保存状态，未开放的操作有明确说明。
