# CiteRAG：经审核的只读 MCP 免逐次审批（设计稿待完整审阅）

日期：2026-10-06。已确定的产品边界：用户同意“可信只读、限定范围免审批”；来源、实际行为、数据去向、权限须在注册时审核；目标、版本、参数范围、权限变化须重新审核；私有资料外发、付费、写操作须另行审批。首版免审批限于我们能控制部署、核实版本的只读服务；无法核实部署的第三方 MCP 逐次审批；仅明确的公开参数可免审批，自由文本和文件内容等仍审批；缺审核记录或配置变化则恢复审批。本稿是上述边界的具体设计，仍待完整审阅，尚未改变运行行为。

## 当前代码与缺口

- `backend/app/tools/mcp.py` 的维护者注册文件固定服务 URL、版本和完整工具 descriptor；执行前重查服务版本、descriptor 和输入 schema，并限制连接到登记 URL，不自动接纳发现的工具。当前 `ReviewedMCPTool.approval_required` 省略时为 `false`，仅校验它是布尔值；“免审批”没有可核对的审核依据。
- `backend/app/tools/gateway.py` 的 `ToolDefinition` 已有 `scope`、`effect`、`destination`、`approval_required`、`policy_hash`；`ToolGateway` 已处理审批、幂等、单会话串行、持久记录。Agent 步骤已绑定 `policy_hash`，MCP `version` 已含 URL、策略和 descriptor 摘要。可复用这些机制，不另建执行通道或数据库表。
- 现有 MCP 工具统一构造为 `effect=read_only`，这不是对远程真实行为的证明。现有客户端没有用户 MCP 凭据注入；也没有可验证远程部署物或服务权限的通用协议证明。

## 已确定的首版边界

1. **缺省需审批。** 所有 MCP 条目在缺少有效免审批审核记录时，均采用 `approval_required=true`。旧登记中省略该字段或写 `false`，不得因旧默认值继续自动执行。现有本地内置工具和天气工具维持各自策略。
2. **免审批只授予单个工具的受限调用。** 首版仅允许维护者控制部署且能核实版本的只读服务；无凭据、无付费、无外部写入，参数只包含已审查的公开数据类型。适合自动判断的是有限枚举、明确范围的数值、固定公开标识；任意自由文本、知识库正文、文件内容、凭据和其他可能含私有信息的参数不进入免审批范围。参数符合工具 schema 却超出豁免范围时，走现有逐次审批；不符合工具 schema 时仍直接拒绝。不能由服务自报 `readOnly` annotation 自动取得豁免。
3. **注册时留审查证据。** 在维护者注册条目的每个工具下新增明确的 `unattended_read_review` 对象，仅该对象完整且通过校验才可能免审批。至少记：审核人和日期、可访问的证据引用（无秘密）、服务来源及已核对的发布/部署标识、实际读操作与副作用说明、允许的数据类别及参数约束、接收方/数据去向、凭据/权限范围（首版必须为空）、收费状态（首版必须免费）、适用的固定 URL、服务器版本和完整 descriptor 摘要。审核记录应随受控配置留存，不能只依赖远端自述；启动时按严格字段校验，未知值拒绝豁免。`approval_required=false` 不能单独构成信任证明。
4. **执行前复核。** 网关先验证已规范化参数是否落在审核许可范围，再决定自动执行或进入现有审批路径。此检查同时用于手动调用和 Agent 调用；Agent 的延迟执行还须复核 `policy_hash`。MCP 适配器继续在每次调用前核对固定 URL、服务版本、完整 descriptor 和参数 schema。审核记录及参数限制写入策略摘要；旧待审批记录仍按现有版本、参数摘要及策略检查失效。
5. **变更失效。** URL/目标、服务版本、descriptor、参数 schema 或许可范围、实际权限/凭据、数据去向、收费状态或审核证据发生变化时撤销原豁免，重新人工审查。已发出的调用只保留原审计记录，不自动重放。对于不能从 MCP 协议核验的服务内部行为或权限变更，运行时无法保证自动发现：首版免审批限定在维护者控制部署且能核实版本的服务；无法核实部署的第三方服务保持逐次审批。即使固定版本和 descriptor 未变，服务被原地替换仍是残余风险，需靠部署管控和复审处理。

## 最小代码落点及测试

- `mcp.py`：解析并验证审核对象，生成“已审查的免审批范围”；默认按需审批。保持现有注册 URL、descriptor、schema、传输限制；不增加 OAuth、凭据或远程服务调用。`gateway.py`：把当前仅由 `spec.approval_required` 决定的建单和执行分支，统一改由“此调用是否须审批”的判断结果驱动；该判断在持久化 `ToolCall` 前用规范化参数运行，并把审查范围纳入 `policy_hash`，供 Agent 和待审批恢复复核。更新 `backend/TOOLS.md` 与登记模板，说明旧 `false` 配置须补审或转为审批。
- 单元测试：无审核/错误类型/自述 `readOnly`/旧 `false` 均要求审批；合格公开参数免审批；私有或超范围参数仍需审批；写、付费、带权限条目不能豁免；URL、版本、descriptor、许可参数、凭据权限和审查记录改变使原豁免无效。
- 隔离集成测试：合成 MCP 的手动调用和 Agent 调用分别验证免审批路径、审批路径、审计、幂等和延迟执行时策略变更；模拟服务版本或 descriptor 变化时拒绝发出 `call_tool`。只用隔离 PostgreSQL 和本地合成服务，不访问真实供应商或业务库。

## 已确认的产品选择与文档审阅

首版免审批**仅限维护者控制部署且能核实版本的服务**；无法核实部署的第三方服务维持逐次审批。仅靠 MCP 自报版本及 descriptor 无法证明远端实际代码和权限一直未变。此产品选择已确认，无需重复决策。审核对象的具体字段名、校验方式与测试案例属于实施细节；请先完整审阅本设计稿，再进入实施计划。
